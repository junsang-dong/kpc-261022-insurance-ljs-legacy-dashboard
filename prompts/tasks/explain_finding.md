아래 탐지 항목 1건에 대해 개발자가 바로 조치할 수 있도록 설명하라.

- `cause`: 왜 문제가 되는가 (어떤 버전부터 어떻게 바뀌었는가). 2~3문장.
- `impact`: 방치하면 어떤 오류·위험이 생기는가. 2문장 이내.
- `replacement`: 대체 방법 요약. 해당 규칙의 가이드(규칙 카탈로그의 `guidance`)와 모순되지 않게 쓴다.
- `codeBefore`: 입력 스니펫을 기반으로 한 변경 전 코드 (최대 15줄).
- `codeAfter`: 변경 후 코드 (최대 15줄). 확신이 없으면 주석으로 "확인 필요"를 남긴다.
- `cautions`: 적용 시 주의사항 최대 4개. 해당 항목의 전환 Step과 선행 조건을 포함한다.

현재 버전과 목표 버전이 주어지면 그 구간에 맞춰 설명하고, 한 번에 여러 축을 바꾸라고 제안하지 않는다.
