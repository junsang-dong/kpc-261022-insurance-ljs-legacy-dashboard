아래 Ref 요약(감지된 버전, 축별 점수, 규칙별 탐지 건수)을 바탕으로 목표 스택까지의 전환 계획 초안을 작성하라.

- `summary`: 현재 위치와 가장 큰 위험을 3문장 이내로 요약.
- `steps`: 아직 남은 Step만 포함하고 이미 끝난 Step은 생략한다. 각 Step에 대해
  - `tasks`: 구체적인 작업. `relatedRuleIds`에는 입력에 실제 존재하는 규칙 ID만 쓴다. `effortHours`는 입력의 건수·규칙 정보에서 근거를 댈 수 있는 값으로 추정한다. `prerequisite`는 선행 조건(없으면 "없음").
  - `risks`: 해당 Step의 주요 위험.
- 한 Step에는 한 종류의 축 변경만 담는다. Java 21 재빌드와 클라우드 구성 변경을 같은 Step에 섞지 않는다.
- 입력에 없는 탐지 항목을 만들어내지 않는다. 모르는 항목은 작업 제목에 "확인 필요"를 붙인다.
- 이 결과는 사람이 항목을 골라 체크리스트·리스크에 반영하는 제안이다.
